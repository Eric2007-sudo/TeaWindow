# 第八轮：第四轮全面复测 P0/P1 整改

> 依据：`TeaWindow产品第四轮全面复测报告_2026-10-14.md`（综合 76/100、专项 67/100）。
> 目标：日期窗口、目标日期共享、上下文实体、数据权威深答与稳定性。测试：`python -m pytest -q` → **69 passed**。

## 一、未来窗口（P0）
- `qa.nlg.classify_ctx` 与 `/api/days?scope=forecast`：**先过滤 `date >= Asia/Shanghai 业务今天`**，再取 N 天；修复"未来 7 天"混入过去两天。
- 证据：`test_future_window_excludes_past`、`test_days_forecast_scope_future_only`。

## 二、复合问题共享 target_date（P0）
- 新增 `nlg.day_detail`：当问题含**目标日/时段 + 多个字段**（温度/降水/霜冻/概率/风险/适宜度）时，所有字段取自**同一目标日**，并附集合区间；无目标日时给"逐日字段列表"。
- 避免"温度用 10-20、降雨回退通用 7 天"的混用。
- 证据：`test_composite_single_target_date`。

## 三、内部超时与降级（P0）
- `/api/ask` 自研问答在**线程池内执行并设 `ASK_TIMEOUT`（默认 8s）**，超时/异常均返回安全兜底文案，不再阻塞 60s；LLM 改写超时 60s→20s。
- （检索索引已改为惰性分批，避免请求期重算。）

## 四、输出业务校验（P0）
- 新增 `engine._final_guard`：非春采期**拦截任何采摘措辞**；指定日期问题须把目标日落到正文；统一去除占位符。

## 五、灌溉安全（P0）
- `drought`：仅当 `ET0−降水 ≥ 45mm` 或土壤含水 < 0.25 才建议灌溉；**连续少雨但亏缺未达阈值 → "先测量根层墒情，暂不直接灌溉"**；标注土壤水分为模式估计。
- `day_advice` 同步：亏缺未达阈值时给"先测墒"而非"浇透"。
- 证据：`test_irrigation_safety_measure_first`。

## 六、上下文实体（P1）
- 从上一轮 user/assistant 文本**提取目标日期**并在追问/指代时携带；"那一天采取什么措施"直接按上一目标日给行动。
- 证据：`test_entity_carry_target_date`。

## 七、通用复合拆解（P1）
- `engine._compound_intents`：风险/来源/模型/动作/具体灾害等线索 → 最多逐项回答 3 项；字段型问题不误拆。
- 证据：`test_compound_three_topics`（"今天风险多少、数据哪来的、我该做什么"→ 三项）。

## 八、数据权威性深答（P1）
- `data_source` 分诊：**现场传感器站数**（读 SQLite 实时计数）+ 模式/台站/遥感/现场区分；**台站距离/偏差**（7.1km、Tmin +2.88℃）；**真实验证边界**（无真实标签/盲测）；**可点击来源链接**。
- 证据：`test_data_authority_sensor_question`。

## 九、历史范围文案（P1）
- 区分"数据仓库 2015 至今"与"聊天当前加载近 180 天 + 16 天预报"；2024 年不再被说成"超出 2015 至今"。
- 证据：`test_historical_range_message_not_2015`。

## 十、前端与契约（P2）
- 非春采期首页"今日行动建议"改为**养护任务**（不再 `–`）。
- `AskResp.chain` 强类型 `list[str]`；各页面加 `<link rel="icon" href="data:,">` 消除 favicon 404。
