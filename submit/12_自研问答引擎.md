# 自研问答引擎（不是 DeepSeek 外壳）

> 原则：问答只是"对话外壳"，**智力来自我们自建的数据流与自训模型**——数据拉取 → 建数据集 → 训练模型 → 问答调用我们的模型并给出**来源链**。DeepSeek 仅作**可选**表述增强。

## 一、完整数据流（我们的价值）
```
① 数据拉取   Open-Meteo / Meteostat / GIBS-S2 / DEM / 官方开采日 / 新闻访谈
② 数据集构建  指标表 · 弱标签 · 灾情事件库 · 物候真值 · **问答语料/意图标注**
③ 模型训练   [本机·numpy] 复合风险 GBDT · 物候 GDD · **意图分类器(自训)**
             [GPU·8×4090] **BERT 意图分类(微调)** · **BGE 语义嵌入(对比学习)**
④ 问答引擎   意图识别 → 槽位 → 调用我们的模型/数据 → 接地生成 + **来源链**
⑤ 对话外壳   chat UI（默认自研；可选 DeepSeek 增强）
```

## 二、本机自研引擎（部署默认，纯 numpy，离线可跑）
- 位置：`src/qa/{build_corpus,train_intent_local,engine}.py`
- 意图分类器：字符 1–2gram + softmax 逻辑回归，**在 tea农口吻语料上自训**。
- 语料：`data/qa/intents_train.jsonl`（含增广）、`knowledge.json`（事实库）。
- 评测：**76.8%**（分层 125 条评测；挑战集 82.2%）——本机兜底模型。生产优先用 GPU 蒸馏的 **ONNX 学生（91.2%）**，缺失时回退本模型。见 `report/qa_gpu_round3.md`。
- 接地生成：答案由 `web/data.json`（风险/调度/决策/保险/价值/物候）+ 我们训练的模型输出拼装，并附**来源链**（数据→模型→依据）。

## 四、蒸馏尝试（诚实记录）
- 用 GPU-BERT 对 4000 条合成问句打伪标签，尝试蒸馏进本机 numpy 模型（第三轮用干净增广重试）。
- 结果：**伪标签过拟合，精度下降**（未蒸馏 75.7% → 噪声伪标签 50.0% / 干净伪标签 52.7%），已**回退**。
- 结论：小语料下蒸馏收益不稳定；后续需更大真实语料与置信过滤（详见 `report/qa_gpu_round3.md`）。

## 五、来源/署名
- `/api/ask` 默认 `engine=own`，返回 `{engine:"teawindow-own", intent, confidence, chain, text}`。
- 前端 `web/chat.html`：显示"引擎：TeaWindow 自研"与**来源链**；勾选后才用 DeepSeek 增强。
- 日报表 `advice` 仍为 DeepSeek 生成 → **保留来源标注**（按既定规则：用自研模型才改品牌）。

## 六、部署取舍
- 免费层/Render 与离线：使用 **numpy 自研引擎**（无 torch 依赖）。
- BERT/嵌入需 torch：可在 GPU 或本地安装后启用（机制已备，`gpu/`）。

## 七、M1–M4 结果（自然语言生成改造）
- **M1 自研 NLG 重写（已上线）**：结论先行 + 条件分支 + **多变体** + 数值接地 + **简洁/详细分档**（触发词：详细/为什么/依据/展开…）。已解决"答案同质化"。
- **M2 数据到文本集**：`src/qa/build_d2t.py` 合成 3240/360 条 chat 样本。
- **M3 GPU 微调**：Qwen2.5-0.5B-Instruct 全参微调（loss→0.023）；ONNX fp32 导出成功（1.4G），int8 量化异常。
- **结论（诚实）**：0.5B 生成模型在**分布外问法出现事实性错误**（"无霜冻"答成"要防冻"），**不接入生产**；生产用 **L1 规则引擎**。后续：更大基座 + 事实约束解码 / 仅做润色 + 校验层。详见 `report/qa_d2t.md`。
- 注：DeepSeek 仍仅**可选润色**。

## 八、M3+ 更大基座 + 事实约束解码（改进）
- 基座升级到 **Qwen2.5-1.5B-Instruct**（部分微调，2 epochs，loss→0.027）。
- **事实约束解码**：多候选生成 + **校验器**（数值/日期须原样、结论须与事实一致）+ **不达标回退规则**。
- 评测：安全用例**生成正确(score=1.0)**，风险不一致用例**自动回退规则** → **自然度与事实正确兼顾**。
- 部署：生成模型本地/GPU 端；Render 用 L1 规则；训练后已释放 GPU。脚本：`gpu/train_d2t_big.py`、`gpu/infer_constrained.py`。

## 九、多轮上下文
- `/api/ask` 支持 `history`；`web/chat.html` 携带最近轮次；引擎识别"追问"（那…呢/详细/为什么）并**继承上一话题与时效**，避免重复、支持多轮。

## 十、问答业务不变量（对照四轮评测整改）
- **季节/时区**：统一 `season.py` 策略对象 + **Asia/Shanghai** 业务日；非春采期全意图禁采摘。
- **日期槽位**：今天/明天/后天、绝对日期、历史日期、`48/24小时` 时段；`rain_max`（哪天雨最大）、`compare`（两日对比）。
- **同一目标日口径**：复合字段问题（温度/降水/霜冻/概率/风险）全部取自同一目标日，并给集合区间。
- **实体级上下文**：从上一轮提取目标日期并在追问/指代中携带（"那一天措施"按目标日作答）。
- **复合拆解**：风险+来源+动作逐项回答。
- **输出完整性**：`season.clean_text` + `engine._final_guard` 保证无 `None`/NaN/空动作。
- **历史范围透明**：区分"仓库 2015 至今"与"聊天近 180 天 + 16 天预报"。
- **数据权威深答**：现场传感器站数、台站距离/偏差、验证边界、可点击来源。
- **稳定性**：`/api/ask` 线程池 + 内部超时（默认 8s）降级，避免长尾阻塞。
