# 硬件接入 10 分钟指南（传感器 → TeaWindow）

> 目标：任意能发 HTTPS 的采集器（ESP32 / 树莓派 / 网关）在 10 分钟内把观测接进 TeaWindow，
> 并在 `/api/realtime`、`/api/sensors` 与「地块风险图」上看到自己的站点。
> 全部接口与字段见 `submit/16_数据治理与接口.md` 第十三节。

---

## 0. 你需要准备
| 项 | 说明 |
|---|---|
| `BASE` | `https://teawindow.onrender.com` |
| `station_id` | 自定义唯一站点名，如 `MWXG-01`（**支持多站**，每个探头一个 id） |
| `lat / lon` | 茶园地块坐标（梅家坞 AOI：120.089–120.104E，30.207–30.222N） |
| 令牌 | **A. 共享令牌** `SENSOR_TOKEN`（最简单）；**B. 设备令牌 + 签名**（推荐上线用） |

---

## 1. 注册站点（一次即可）
```bash
curl -sS -X POST "https://teawindow.onrender.com/api/station" \
  -H "Content-Type: application/json" \
  -H "X-Sensor-Token: <SENSOR_TOKEN>" \
  -d '{"station_id":"MWXG-01","name":"梅坞溪谷1号","lat":30.2139,"lon":120.0961,"plot":"梅坞溪谷"}'
```
成功后：`{"ok":true,"station_id":"MWXG-01","count":N}`。站点会出现在「地块风险图」的蓝色标记上。

---

## 2. 上报一条观测（方案 A：共享令牌，最省事）
```bash
curl -sS -X POST "https://teawindow.onrender.com/api/sensor" \
  -H "Content-Type: application/json" \
  -H "X-Sensor-Token: <SENSOR_TOKEN>" \
  -d '{"station_id":"MWXG-01","ts":"2026-10-17T14:30:00+08:00",
       "temp":18.6,"rh":82,"soil_moisture":0.31,"soil_temp":17.9,"precip":0,"wind":1.2,"light":22000,"vpd":0.6}'
```
返回：`{"status":"ok","accepted":1,"count":N}`；重复的 `(station_id, ts)` 会**幂等去重**（`accepted=0`）。

**时间格式**：ISO8601，建议带时区（`+08:00`）；UTC 用 `Z` 亦可。**字段单位**：

| 字段 | 单位 | 说明 |
|---|---|---|
| `temp` | ℃ | 2m 气温（或茶蓬层） |
| `rh` | % | 相对湿度 |
| `soil_moisture` | m³/m³ | 体积含水（0–1） |
| `soil_temp` | ℃ | 根层土温 |
| `precip` | mm | 时段降水 |
| `wind` | m/s | 风速 |
| `light` | lux | 光照（可选） |
| `vpd` | kPa | 饱和水汽压差（可选） |

批量（≤500 条，适合网关补传）：
```bash
curl -sS -X POST ".../api/sensor/batch" -H "X-Sensor-Token: <T>" -H "Content-Type: application/json" \
  -d '{"readings":[{"station_id":"MWXG-01","ts":"...","temp":18.6},{"station_id":"MWXG-01","ts":"...","temp":18.2}]}'
```

## 3. 上报（方案 B：设备令牌 + HMAC 签名，推荐）
### 3.1 让管理员发一个设备令牌
```bash
curl -sS -X POST "https://teawindow.onrender.com/api/device/register?device_id=mw-tea-01" \
  -H "X-Admin-Token: <ADMIN_TOKEN>"
# → {"device_id":"mw-tea-01","token":"<仅显示一次，请安全保存>"}
```
服务端**只存 token 的哈希**，可随时 `POST /api/device/revoke?device_id=mw-tea-01` 撤销。

### 3.2 签名规范（逐字照做）
```
key       = sha256(token) 的十六进制字符串
canonical = X-Timestamp + "\n" + X-Nonce + "\n" + METHOD + "\n" + PATH + "\n" + sha256(raw_body)
X-Signature = HMAC_SHA256(key, canonical) 的十六进制字符串
```
- `X-Timestamp`：ISO8601（与服务器时差 **±300 秒**内）；
- `X-Nonce`：每请求唯一（重复 → **409 replay**）；
- `raw_body`：**实际发送的字节**（务必与签名一致，勿重新序列化）。

### 3.3 Python（树莓派/网关）示例
```python
import hashlib, hmac, json, secrets, requests
from datetime import datetime, timezone

BASE   = "https://teawindow.onrender.com"
DEVICE = "mw-tea-01"
TOKEN  = "<设备令牌>"

payload = {"station_id": "MWXG-01", "ts": datetime.now(timezone.utc).astimezone().isoformat(timespec="seconds"),
           "temp": 18.6, "rh": 82, "soil_moisture": 0.31}
body  = json.dumps(payload, separators=(",", ":"), ensure_ascii=False).encode("utf-8")
ts    = datetime.now(timezone.utc).isoformat(timespec="seconds").replace("+00:00", "Z")
nonce = secrets.token_hex(8)
key   = hashlib.sha256(TOKEN.encode()).hexdigest()
canonical = "\n".join([ts, nonce, "POST", "/api/sensor", hashlib.sha256(body).hexdigest()])
sig   = hmac.new(key.encode(), canonical.encode(), hashlib.sha256).hexdigest()

r = requests.post(BASE + "/api/sensor", data=body, timeout=20,
                  headers={"Content-Type": "application/json", "X-Device-Id": DEVICE,
                           "X-Timestamp": ts, "X-Nonce": nonce, "X-Signature": sig})
print(r.status_code, r.text)
```

### 3.4 ESP32（Arduino）要点
- `WiFiClientSecure` + `HTTPClient`，`setInsecure()` 仅调试用，正式请校验证书；
- NTP 校时后生成 `ts`（`strftime("%Y-%m-%dT%H:%M:%SZ")`）；
- 用 `mbedtls_md_hmac`/`SHA256` 计算 `key=sha256(token)` 与 `sig=HMAC(key, canonical)`；
- **payload 用固定字符串**（不要依赖 JSON 库输出顺序），签名与发送用**同一份字节**。

## 4. 验证是否接上
| 检查 | 方式 |
|---|---|
| 站点已登记 | `GET /api/sensors` → 你的 `station_id` |
| 最新观测 | `GET /api/realtime` → `stations[station_id]`（含 `age_seconds/status`） |
| 地图可见 | 打开 `/terrain.html` → 蓝色站点标记 |
| 管理审计 | `GET /api/devices`（管理员）→ `active` 与最近审计 |

---

## 5. 常见错误
| 状态 | 原因 | 处理 |
|---|---|---|
| **403** | 没有/错误的 `X-Sensor-Token` | 用 `SENSOR_TOKEN` 或设备令牌 |
| **401 incomplete** | 只传了部分签名头 | 四个头要么都传、要么都不传 |
| **401 bad signature** | `raw_body` 与签名不一致 / key 算错 | 先 `sha256(token)` 再 HMAC；发送原始字节 |
| **401 timestamp skew** | 设备时间偏差 >300s | 开 NTP 校时 |
| **409 replay** | nonce 复用 | 每请求生成新 nonce |
| **429** | 超过 `SENSOR_RPM`（默认 120/min） | 降频或批量上报 |

---

## 6. 安全与隐私
- 令牌只放**请求头**，不要放 URL 参数；
- 设备令牌**只显示一次**，服务端仅存哈希，可撤销；
- 公开只读接口仅返回数值与时间，不含备注/身份；
- 建议：生产用**设备令牌 + 签名**；试点期可先用共享令牌。

## 7. 让"示例站点"变成真实站点
当前线上有 2 个**示例站点（仅坐标、未接硬件）**：`DEMO-MWXG`、`DEMO-BPO`。
接入真实探头后：
1. 用真实 `station_id` 注册（如 `MWXG-01`）；
2. 开始上报；
3. 如需下线示例：`POST /api/device/revoke?device_id=DEMO-MWXG` 只撤销设备令牌，示例站点记录可保留作占位，或在数据库删除该行（管理员操作）。
