# 为什么需要"领域智能问答"（而不是直接用通用 LLM / 联网搜索）

> 用途：回应评审与社区常见疑问——**DeepSeek 能联网搜索，为什么用户会用 TeaWindow 的智能问答？**
> 结论：**我们不是"更便宜的 DeepSeek"，而是"把通用大模型放回它该在的位置"的领域决策助手：通用模型负责"说人话"，我们负责"说对话"。**

## 一、通用 LLM（含联网）做不到的四件事

| 维度 | 通用 LLM + 联网搜索 | TeaWindow 智能问答 |
|---|---|---|
| **粒度** | "杭州今天多云 18–25℃" | "你这块**北坡低洼地**下推 Tmin 3.2℃、霜冻易感**高**，今夜建议覆盖/熏烟，明晨再看" |
| **决策** | 给信息，不给"该不该做" | 直接给**该采 / 该防 / 该灌 / 该排** + 为什么（附来源链） |
| **可追溯** | 网络片段、来源不明、无法复算 | 上游 URL / 参数 / 完整 SHA-256 / 数据版本；**同问同答**、131 项回归测试 |
| **闭环** | 一次性问答 | 接 **传感器 / 田间上报 / 告警（钉钉）/ 地块地形下推**，形成"预测→行动→反馈→校准" |

联网搜索拿到的是**公开常识**；拿不到"你的地块 + 当日复合风险 R + 采摘窗口 + 项目已算好的结果"。

## 二、农业场景特有的"不能靠感觉"
- **幻觉代价高**：说错霜冻/排水会真亏钱 → 必须**规则/模型接地 + 来源链 + 数据过期降级**；
- **可审计**：出问题要能回答"凭什么这么说"（版本、参数、哈希、误差指标 POD/FAR/MAE）；
- **隐私合规**：地块与农事数据不应外送公网大模型 → 匿名日志 + 管理员审阅，不同用户互不可见；
- **可用性/成本**：可 CPU 运行、**规则兜底**（断网/无 LLM 也能答核心问题），免费层可部署。

## 三、谁会用、什么时候用
- **会用**：合作社 / 茶企 / 农技员在**现场、弱网、要担责**的场景——要"一句能执行的话"和"能对账的来源"。
- **不会用**：问"今天杭州天气""龙井历史"等**通用知识**——那种场景通用 LLM/搜索更合适；我们也**主动拒答**（这是特性，不是缺陷）。
- **一句话定位**：> 通用大模型负责"说人话"，我们负责"说对话"。

## 四、我们如何把价值做锋利（已落地 / 在推进）
1. **把"问"绑到"地块/事件"**：地形图点选任一位置 → 自动生成该点数据（海拔/坡度/坡向 + 下推 Tmin/Tmax + 风险 R + 建议）→ 一键追问（已上线）；
2. **把历史接进来**：问答直接读**传感器与田间 outcome**（"你这块地昨天上报受冻，今天 R=…，建议…"），形成真正闭环（接口已就绪，待装探头）；
3. **保持边界**：始终标注"决策辅助"，不替代田间实勘与官方预警。

## 五、诚实边界
- 我们**不替代官方预警**，也**不做通用百科**；
- 现有精度为"弱标签 + ERA5 对照"，**尚无田间真值** → 定位是**决策辅助**；
- 通用 LLM 在我们的架构里是**可选润色层**（仅改写表述、不作智力来源），并已用于"使用→教师纠偏→回训"的语料闭环。

---

### 一句话（可直接放材料/答辩）
> 当问题是"**我该怎么办**"，而且要**可执行、可追溯、可问责**时，通用 LLM 给不了，我们能给；当问题只是"**世界是什么样**"时，用 DeepSeek 就好——我们甚至可以只让它替我们润色表述。
