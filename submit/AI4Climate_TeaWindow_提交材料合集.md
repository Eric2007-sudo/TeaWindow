# 项目说明 · 梅坞采候 TeaWindow

> **赛道**：AI4Climate 全球青年气候解决方案挑战赛 · 01 梅家坞气候智慧茶园
> **项目名**：梅坞采候（TeaWindow）——梅家坞龙井 43 号「倒春寒 × 高温」复合风险预警与采摘窗口决策助手
> **形态**：可离线运行的单页 Web 原型 + 开源代码仓库 + AI 分析报告

---

## 一、问题：真实、具体、有边界

梅家坞是西湖龙井核心产区，约 **70%** 茶园种植**特早生、抗旱弱**的**龙井 43 号**，因此同时暴露于两类气候风险：

- **春季倒春寒/霜冻**：萌芽早（2 月上旬萌动），嫩芽遇晚霜易红变焦枯。**2010 年**一次冻害使浙江 150 万亩茶园损失约 **17 亿元**，西湖区近 3 成茶园受冻、开采推迟约 10 天。
- **夏季高温/伏旱**：**2020、2022 年**西湖区约 **5000 亩**茶树顶部灼伤，个别茶园减产约 1/3；**2024 年**杭州高温日 **60 天**破纪录（8/3 达 41.9℃），且影响来年春茶。
- 两类风险叠加**连阴雨/台风**，构成**复合风险**，信号来源分散、年际波动大，茶农难以判读。

**边界**：本项目聚焦"**风险识别 + 采摘/养护决策**"，不做产量预测、不做病虫害识别；面向**梅家坞地块尺度**，方法可迁移至其他龙井产区。

**证据**：2015–2026 年逐日气象实测算得——霜冻日年均约 60–76 天、倒春寒年均 2–11 次、高温日 2022 年 28 天/2024 年 24 天；见报告 `report/figures/fig_yearly.png`。

## 二、目标用户与受益方

| 角色 | 需求 |
|---|---|
| **梅家坞茶农**（主要用户） | 明天采不采？要不要遮阳/灌溉/防冻？ |
| **采茶队/管理者** | 何时组织采工、抢采窗口 |
| **合作社/茶企** | 鲜叶计划、品质稳定 |
| **受益方** | 产区品牌与消费者（品质与价格稳定） |

## 三、AI 任务：具体且必要

1. **农业气象指标引擎**：有效积温(GDD)、霜冻、倒春寒(前期偏暖后骤冷)、高温、干旱(10 日水分亏缺+土壤湿度)、连阴雨。
2. **复合风险识别（核心 AI）**：**纯 numpy 梯度提升树(GBDT)** 融合多变量与交互项，输出**逐日复合风险度与风险等级**。
3. **采摘适宜度与窗口**：透明规则给出 0–100 适宜度与未来最佳采摘窗口。
4. **遥感植被活力**：NASA GIBS MODIS NDVI 时序（近似反演）+ Sentinel-2 场景接入。
5. **LLM 白话建议**：DeepSeek 把指标转成茶农可执行的中文建议（无密钥降级规则模板）。

**为什么 AI 必要**：单一阈值（如仅 Tmin≤2℃ 判霜冻）只能覆盖霜冻、误报高；在 2024–2025 留出年，
**多变量 GBDT：AUC 0.998 / F1 0.854**，**单阈值基线：AUC 0.780 / F1 0.498**。AI 的价值在于
**融合气温+湿度+水分亏缺+物候的复合交互**，并**可前推至预报期**给出连续、可解释的风险。

## 四、方案逻辑

```
Open-Meteo 气象(历史+预报)      NASA GIBS / Sentinel-2 遥感
        │                              │
        ▼                              ▼
  农业气象指标引擎              植被活力(NDVI)
        └──────────┬──────────────────┘
                   ▼
        GBDT 复合风险识别 → 风险等级(低/中/高/极高)
                   ▼
        透明规则：采摘适宜度 + 最佳窗口
                   ▼
        DeepSeek/规则后备：白话行动建议
                   ▼
        单页离线仪表盘（可运行 Demo）
```

## 五、创新点与差异化

官方气象服务已提供"积温开采期预报模型""霜冻智能识别短信""气象风险溯源"，本项目**不重复、做增量**：

| 维度 | 官方现状 | TeaWindow 增量 |
|---|---|---|
| 粒度 | 区域级 | **地块级**（可扩至坡度/坡向/土壤） |
| 风险 | 以霜冻为主、单一 | **倒春寒×高温×干旱×连阴雨复合** |
| 输出 | 气象要素/短信 | **可行动的采摘窗口与养护建议** |
| 用户 | 部门/管理者 | **直接面向茶农**，低门槛 |
| 闭环 | 预警→短信 | **预警→行动→反馈→验证** |

## 六、可运行成果

- **离线 Demo**：`web/index.html`（数据内嵌、图表库本地化，双击即可运行）
- **代码仓库**：`src/`（数据管线、指标引擎、遥感、模型、LLM、导出、图表）
- **模型与报告**：`models/metrics.json`、`report/analysis.md`

## 七、市场可持续性

- **受益方/付费方**：茶园合作社、茶企、产区数字农业服务商、气象/保险场景。
- **成本结构**：数据全部公开免密钥；算力需求极低（纯 numpy，可在本地/边缘运行）。
- **持续逻辑**：可嵌入合作社的春茶调度、茶企的品质管理，或作为气象/农险的增值服务接口。

## 八、传播与公众采用

- **白话建议**：把复杂指标转成"采/防/灌"的一句话行动。
- **可视化仪表盘**：风险/适宜度时间线、气温与霜冻高温信号、NDVI 活力。
- **可感知的价值**：让茶农"看得懂、用得上、有反馈"。

## 九、扩展性、伦理与开放性

- **扩展性**：换坐标与产区参数即可迁移到其他龙井/绿茶产区；方法通用。
- **伦理与安全边界**：明确为**决策辅助**，不替代官方预警与农技指导；灾害信息需人工复核。
- **诚实声明**：模型为**弱标签监督**（专家规则生成标签），并公开遥感近似反演等不确定性。
- **开放性**：数据来源公开、代码可复现、方法透明。

## 附：数据与 AI 说明（摘要，详见 `report/analysis.md`）

| 项 | 内容 |
|---|---|
| 气象 | Open-Meteo（ERA5 历史 2015–2026，4301 天 + 16 天预报），免密钥 |
| 遥感 | NASA GIBS `MODIS_Terra_NDVI_8Day`（颜色近似反演）+ Element84 STAC `sentinel-2-l2a` |
| 模型 | 纯 numpy GBDT（深度 3，250 棵），训练 2015–2023 / 测试 2024–2025 |
| 指标 | 有效积温、霜冻、倒春寒、高温、干旱、连阴雨 |
| LLM | DeepSeek `deepseek-chat`（可选），无密钥降级规则模板 |
| 评估 | AUC 0.998 / F1 0.854（vs 单阈值基线 AUC 0.780 / F1 0.498） |

# 验证计划（90 天）

> 项目：梅坞采候 TeaWindow　|　赛道：AI4Climate 01 梅家坞气候智慧茶园
> 目标：在 **90 天内**，用**小范围、低风险**的真实场景测试，验证模型的**准确性、可用性与减灾价值**。

---

## 1. 验证目标与假设

| # | 假设 | 验证方式 |
|---|---|---|
| H1 | 模型能准确识别霜冻/高温/干旱复合风险日 | 与茶农记录的历史受灾事件比对（回测） |
| H2 | 面向茶农的建议可被理解并采纳 | 试点用户每日使用记录 |
| H3 | 采纳建议能减少损失/无效作业 | 试点期受冻/灼伤/无效抢采对照 |
| H4 | 方案可低成本、可持续运行 | 运行成本与用户留存统计 |

## 2. 范围与对象

- **地点**：梅家坞（西湖龙井核心产区），**3–5 户茶园**，覆盖**高脆弱**（幼树/浅根/薄土/平地）与**低脆弱**（坡地/成龄树）地块。
- **用户**：茶农 + 采茶队管理者（每日使用者）。
- **时间**：连续 **90 天**，覆盖**春季采摘关键期**（优先覆盖 3–4 月倒春寒高发期；若时间不匹配则先做历史回测）。

## 3. 方法与 90 天排期

| 阶段 | 天数 | 内容 | 产出 |
|---|---|---|---|
| **S1 回测（离线）** | D1–D20 | 用近 3 年春茶季，把模型风险日与茶农记录的受冻/灼伤/推迟采收事件逐日比对 | 命中率/漏报率矩阵、混淆矩阵 |
| **S2 试点（在线）** | D21–D75 | 茶农每日查看仪表盘建议，勾选"是否采纳/是否有效"；同步收集监测站真值 | 每日使用日志、建议采纳率 |
| **S3 校准与评估** | D76–D90 | 用真值校准阈值，输出误报/漏报与效果对照；形成结论 | 校准报告、验证总结 |

> 若启动期已过春茶季：S1 先行，S2 在下一个霜冻/高温高发窗口（秋季寒潮或次年 2–3 月）继续，逻辑不变。

## 4. 方法与数据细节

- **回测标签来源**：茶农访谈 + 气象灾情通报 + 田间照片/记录（受冻芽叶、灼伤、延迟开采）。
- **真值气象**：产区自动气象站（若有）或最近官方站，用于与 Open-Meteo 逐日要素比对。
- **评估口径**：
  - 事件级：以"霜冻日/高温日/干旱期"为单位，计算**召回率、误报率、精确率**。
  - 建议级：每条建议的**采纳/未采纳**与**自评有效性**。

## 5. 评估指标与成功标准

| 指标 | 定义 | 成功标准 |
|---|---|---|
| 事件召回率 | 命中风险事件 / 实际风险事件 | **≥ 80%** |
| 误报率（FPR） | 误报风险日 / 非风险日 | **≤ 20%** |
| 建议采纳率 | 被采纳建议 / 推送建议 | **≥ 60%** |
| 用户可用性 | 5 级量表（茶农评分） | **≥ 4.0 / 5** |
| 减灾/增效 | 受冻率、无效抢采次数等对照 | 试点组**较对照改善** |
| 运行成本 | 90 天总成本 | **近乎零数据成本**（全公开数据） |

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 标注数据稀缺（弱标签） | 以田野事件为真值做回测；明确"弱标签"局限，不夸大为实测 |
| 90 天窗口错过春茶季 | 先做历史回测；在线试点顺延至下一个风险高发窗口 |
| 茶农配合度低 | 极简交互（一句话建议 + 一个勾选）；赠送/共享受益 |
| 气象/遥感偏差 | 用官方站真值校准；对不确定性分级提示 |
| 责任与安全 | 明示"决策辅助、不替代官方预警"；灾害信息人工复核 |

## 7. 伦理与合规

- 仅使用**公开数据**与**经授权/模拟**的样例数据；不采集与使用个人隐私信息。
- 涉及地理标志与品牌时遵循**真实性**原则，不协助伪造/擦边。
- 所有预警输出附带**不确定性说明**与**安全边界**。

## 8. 交付物

1. 回测混淆矩阵与命中/漏报表；
2. 试点每日日志与采纳率统计；
3. 校准报告（阈值与误报/漏报）；
4. 90 天验证总结（含成功标准达成情况与改进项）。
