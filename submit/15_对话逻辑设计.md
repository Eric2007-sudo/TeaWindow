# 对话逻辑设计（参考业界 LLM Agent 范式）

> 参考：Anthropic《Building effective agents》(2024-12)、OpenAI 提示工程与 Agent 实践、RAG/工具调用/对话管理通用范式。
> 结论：**优先简单、可组合的模式**；本项目采用"路由 + 检索 + 接地生成 + 校验回退"，而非重型框架。

## 一、借鉴的范式 → 我们的落地
| 范式 | 含义 | TeaWindow 落地 |
|---|---|---|
| **Routing（路由）** | 先分类再分发到专用处理 | `意图分类(自训) + 强关键词` → 15+ 专用处理器（`src/qa/nlg.py`） |
| **Augmented LLM** | LLM + 检索/工具/记忆 | 检索本项目数据与模型输出；`history` 多轮记忆 |
| **Guardrails（分屏值守）** | 单独一层拦截越界 | 空值/英文/医疗金融/超期预测 → 明确边界或澄清 |
| **Evaluator-Optimizer** | 生成后校验再定稿 | LLM **仅润色**，**数值一致性校验**，不通过**回退规则** |
| **Transparency（透明）** | 明确展示步骤与依据 | 回答附**来源链**（数据→模型→依据）与**置信度/意图** |
| **Tool use（工具调用）** | 以工具获取真值 | 引擎"调用"我们的模型/数据（GBDT/物候/保险/调度/传感器） |

## 二、对话能力清单（现状）
- **多轮上下文**：`/api/ask` 携带 `history`；识别**追问**（那…呢/详细/为什么/它/这个/怎么样）并**继承上一话题与时效**。
- **指代日期**：支持"**今天/明天/后天/大后天/第N天**"——回答聚焦到具体某天（风险/霜冻/高温）。
- **逐日清单**：`列举/逐日/未来N天`（含中文数字"三天/五天/七天"）→ **逐日风险表**（仅今天及以后）。
- **澄清与拒答**：低置信→澄清；越界/英文/超期→边界说明。
- **一致性**：数值与结论以**结构化结果**为准，LLM 只做表述（P0-1 整改）。

## 三、System Prompt 设计要点（供 LLM 增强模式）
1. 角色与边界：只服务梅家坞茶园气候与采摘决策；非农业问题不答。
2. 事实优先：只依据给定事实；数值必须原样；不确定就说不确定。
3. 结论先行：先给"要/不要/程度"，再给 1–2 条动作。
4. 不越权：不新增/修改数值与结论（由规则层产出）。
5. 透明：保留来源链与时间尺度。

## 四、评估与下一步
- 已有：小规模边界用例、事件级回测、事实一致性校验。
- 下一步：**预注册问题集 + 盲测**、会话级指标（澄清率、追问解析率、事实一致率）、A/B（自研规则 vs 规则+LLM润色）。
